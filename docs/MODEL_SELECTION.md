# Choosing a model for AutoFactorio

Use explicit routes by uncertainty and verifiability. These are requested developer defaults, not measured quality or subscription savings rankings.

| Work | Model | Effort | Escalate when |
| --- | --- | --- | --- |
| Execution, calculations, polling and reports | Deterministic code | None | Return failed/unknown facts |
| Bounded implementation | `gpt-6.1-sol` | medium | Coupling exceeds the packet |
| Coupled implementation and ownership/recovery | `gpt-6.1-sol` | high | Consequential design remains unresolved |
| Focused tests and exact routine verification | `gpt-6-luna` | medium | Expected behavior or evidence is ambiguous |
| Bounded adaptive browser/evidence verification | `gpt-6-luna` | high | Cross-component uncertainty |
| Uncertain cross-component/recovery verification | `gpt-6.1-sol` | high | Conflicting invariants or repeated correction |
| Bounded unfamiliar diagnosis | `gpt-6-astra` | medium | Return the next discriminating check |
| Bounded spec/plan review (provisional) | `gpt-6.1-sol` | high | Consequential ownership, recovery or cross-component uncertainty |
| Complex spec/plan review | `gpt-6-astra` | high | Return unresolved source questions and coverage gaps |
| Implementation review | Inherit authorized author | Inherit authorized author | Return scoped findings and coverage limits |
| Gameplay agents | Existing `gpt-6-astra` profiles | low | Existing gameplay policy |

The current session is not switched by a recommendation. Before new managed dispatch, validate ChatGPT authentication, requested model/effort and included allowance. `corepack.cmd pnpm dev:task --verify-capability --model <id> --effort <effort>` performs read-only dedicated verification discovery. Unavailable selections block; never silently substitute GPT-6 Sol, GPT-5.6, another provider or API billing. Keep Fast mode off for this user's efficiency preference. Implementation review uses its existing inheritance rule. Spec/plan review uses the [dedicated workflow](../.agents/skills/spec-review/author-workflow.md); its Astra discovery uses the existing generic discovery function, not the verification-only route validator.

Plan bounded tasks with named ownership, interfaces, invariants, failure cases, acceptance checks, model/effort, rationale, shared budget and escalation condition. Delegate test writing once interfaces and behavioral cases stabilize. A worker's new context does not reset spent usage. Unknown accounting requires a recorded bounded decision; no exact subscription balance follows from raw tokens.

Keep automatic compaction defaults. At an independently accepted slice boundary, a fresh context receives a compact packet with current fingerprints, criteria/evidence, invariant/finding lineage, owned resources, shared plan balance and one bounded next action. No per-check compaction cadence, global settings edits or automatic replacement model launches.

For task plans append a `## Model routing` table with columns `Task`, `Role`, `Model`, `Effort`, `Rationale`, `Escalate when`. Give every checkbox ID exactly one row; roles are `author`, `verification`, `review`. Implementation-review rows use `inherit-author` for both route fields. Spec-review dispatch is recorded in its dedicated assignment with an explicit route; it is not launched through the author-task parser, whose review-row format remains unchanged. Migrate only pending active recommendations; keep completed routes, archived history, recorded actual model observations and intentional legacy fixtures unchanged. Explicit overrides require a reason and cannot bypass role or provider rules.

The `dev:task` launcher previews author selections by default and requires `--start`. Dedicated verification and independent review use their [verification](../.agents/skills/verify-change/author-workflow.md) and [review](../.agents/skills/change-audit/author-workflow.md) contracts. Automatic mid-session switching remains deferred. This guidance does not resume a paused milestone or authorize gameplay inference.

On the next separately authorized ordinary task, use [routing-outcome.template.json](examples/routing-outcome.template.json) to record recommendation, observed actual route, escalation, available aggregate usage, rework and acceptance. For spec-review observations, reuse that record and the [three-task follow-up](DEVELOPMENT_EFFICIENCY.md#routing-pilot). The small [local comparison](decisions/024-spec-review-evidence.md) supports a provisional route, not model parity or a savings ranking. Do not start a model benchmark campaign. [Development efficiency](DEVELOPMENT_EFFICIENCY.md) documents local usage and execution reports; actual availability comes from managed discovery rather than documentation.
