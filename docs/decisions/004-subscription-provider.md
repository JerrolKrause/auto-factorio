# Decision 004: subscription provider isolation and bounded probes

Date: 15 September 2026. Scope: phase 02, `af-02-subscription-provider`.

Use Codex 0.154.0 app-server over stdio with managed ChatGPT authentication and exact `gpt-6-astra` / `low` effort. The adapter rejects other builds, API/external-token authentication, model substitution and unavailable included allowance. It exposes no purchase, reset-credit, configuration-write or general admin protocol methods. Unknown allowance remains unknown and withholds new inference in this included-only diagnostic.

Each role has its own process and synthetic workspace. Start threads with the pinned experimental `environments: []` field and require the response's environment selection, runtime workspace roots and instruction sources to be empty. Disable native shell, editing-environment access, browser, computer use, apps/connectors/plugins, native subagents and other bypass sources through per-launch configuration. Disable every inherited MCP server. Read the effective configuration and MCP catalog before turn admission. MCP stays the ordinary Streamable HTTP protocol; experimental dynamic tools are not used.

The runtime issues a random bearer capability for each role/turn generation. Gateway arguments cannot select identity. A completed/interrupted turn permanently revokes its capability. A later turn replaces the role's process and capability and resumes only that role's recorded thread ID. This extra startup cost closes the late-call ambiguity of reusing a credential after admitting a new turn. Source files remain small modules under `packages/codex` and `packages/tools`, compiled by the existing root TypeScript project; no unused framework or additional dependency is needed.

Only the synthetic `autofactorio` MCP server receives `default_tools_approval_mode = "approve"`. Initial omission of that setting caused the first live test's MCP calls to be rejected by Codex under `approval_policy = "never"`; the test did not pass. General approvals remain denied. Per-role catalogs and gateway checks still enforce authorization. A real game gateway and acknowledged game fencing/cancellation are later phases.

Budget counters distinguish submitted provider turns, gateway attempts including rejections, elapsed monotonic time and deduplicated cumulative usage by provider thread. Reported total tokens include cached input and are not an estimate of subscription balance. The run's final admitted turns keep their other limits. Time/token/account exhaustion closes admission before interrupt/cancellation callbacks. An RPC acknowledgement does not prove interruption completion. Terminal events and cancellation acknowledgements have separate states. Counters are plain snapshot data for phase 05 persistence; replacing a provider session does not reset them.

The console writes public events incrementally to ignored JSONL evidence. Reasoning items expose public summaries only; raw provider events are omitted. Unknown notifications retain names and field names, rather than arbitrary potentially sensitive payloads. Normal provider-managed session history remains in Codex's existing session store; credentials are never read or copied. AutoFactorio's evidence, isolated workspaces and logs stay under `.runtime/phase02`.

Protocol bindings were generated from the installed executable, both stable and experimental, into `.runtime/phase02/protocol*`. Handwritten narrow wire projections in `protocol.ts`/the adapter were checked against those bindings. No generated/upstream implementation was copied. The inspected upstream release is `rust-v0.154.0`, commit `6b9826e3aa83b1a5947db50f4332cb9c65f1b340`. Relevant `core/src/tools/spec_plan.rs` checks local environments before registering shell, apply_patch and view_image; effective MCP catalogs come from `mcpServerStatus/list`.

Sources: [official app-server documentation](https://learn.chatgpt.com/docs/app-server), [configuration reference](https://learn.chatgpt.com/docs/config-file/config-reference), [pinned tool registration source](https://github.com/openai/codex/blob/6b9826e3aa83b1a5947db50f4332cb9c65f1b340/codex-rs/core/src/tools/spec_plan.rs), [pinned configuration schema](https://github.com/openai/codex/blob/6b9826e3aa83b1a5947db50f4332cb9c65f1b340/codex-rs/core/config.schema.json).

The current [handoff](../IMPLEMENTATION_HANDOFF.md) records actual trial caps, failures and remaining gate criteria. This decision does not by itself claim a passed live gate or authorize another trial after exhaustion.

Continuation validation, 15 September 2026: the live gate passed after explicitly supplying `environments: []` at every turn start, including resumed histories. The pinned server can restore a local workspace during `thread/resume`; no inference occurs until the next turn explicitly disables environments, and gateway admission waits for the supported thread metadata read to verify that selection. An accepted first turn may briefly have unreadable empty rollout metadata. Retry only that specific read error up to 20 times at 100 ms intervals, retaining RPC and run deadlines; never retry the accepted turn. Persistent/unrelated errors fail closed. The passing live trace exercised four read retries and all four empty-environment checks. The probe now settles both concurrent starts before cleanup and requires retained original history markers, preventing absent history from passing an exclusion-only check. The complete result and usage remain in the handoff.
