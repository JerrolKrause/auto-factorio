# Decision 005: bounded original character executor

Date: 15 September 2026. Scope: phase 03, `af-03-character-execution`. This records implementation boundaries; the handoff records which live gates actually passed.

Use the installed Factorio 2.0.77 build 84539 and Space Age, quality and elevated-rails 2.0.77, with the original `autofactorio` 0.1.0 mod. No upstream action code was copied. Re-read the pinned Agentic-Factorio walking/building implementations listed in decision 003; installed `doc-html/runtime-api.json` is authoritative for this client's Lua signatures.

The Node adapter speaks authenticated loopback RCON. It frames fragmented responses and uses a separate fixed `rcon.print` command as a response delimiter: this engine does not answer an empty command. The gameplay wrapper calls only `autofactorio_v1.rpc`, encoding every UTF-8 JSON byte as a decimal Lua escape. Strict TypeScript and Lua request validators reject raw console/admin operations and extra fields. An authenticated role wrapper denies foreman mutations and actor spoofing. The RCON credential belongs to the application; gameplay tools never receive it.

Use one fixed test assignment (`phase03-actions`, revision 1, grant `test-area` generation 1), a Nauvis area bounded to +/-32 tiles, and explicit actor IDs (`builder-<player index>`). This is a wire-level foundation for later ownership, not dynamic leases. Batches have 1-100 steps, deadlines at most 36,000 ticks ahead, and a 200-order test-session receipt capacity. Observations return at most 50 entities per page, a tick, live-page freshness caveat, scope, coverage, quality, and the complete active mod/version list. Recipe ratios use running-game facts and reject unimplemented fluids, probabilities, multiple outputs and advanced categories.

The disposable fixture clears a small area, supplies a finite kit, disables vanilla intro/crashsite setup, grants research, and protects a chest and short wall. These setup exceptions do not expose resource creation through gameplay. Gameplay leaves normal speed, collision and timing in force. Movement uses engine path requests and per-tick character walking with bounded waits/stuck detection. Crafting and mining use the native character queues/controls; placement uses the player's cursor build API after moving one actual inventory item into that cursor. Rotation, recipe changes and transfers recheck entity identity, quality, reach and protected status. Failures stop the batch with inventory snapshots/deltas and explicit unexecuted remainder. Cancellation neutralizes controls and lets the engine refund cancelled crafting.

Command IDs and per-step receipts live in mod `storage`. Exact repeated intents return their receipt; conflicting reuse is rejected by structural comparison independent of table key order. The Node client treats a lost transport response as unknown and blocks new submissions until a valid matching persistent receipt is observed. It never retries an unknown action blindly.

Operator diagnostics have a separate `autofactorio_operator_v1` interface and are absent from the gameplay validator. Saves are requested only when no orders are active. Loaded worlds reject new gameplay submissions; only the initial empty sandbox's first player creation enables execution. This does not establish phase 04's pause/restore/reconcile/re-arm gate. In particular, active-order checkpoint recovery remains unimplemented and must not be inferred from quiescent receipt readback.

Every launch creates a fresh ignored project data/mod/save/config directory; no game assets are copied. Graphical Steam builds may require Steam launch-option confirmation and a local player name. The project config disables blueprint-library cloud sync for subsequent launches. The initial graphical attempt exposed a controller-initialization error, fixed by selecting the god controller during setup before `create_character`; normal character control follows immediately. Public evidence is NDJSON, with optional operator engine screenshots; screenshots are not model input.


Live topology discovery: the Steam graphical `--host` run loaded the fixture and character but did not open the specified RCON listener (the game log reported host bind `0.0.0.0:0`). The same installed executable in `--start-server` mode honored the explicit loopback game/RCON bindings. Select a dedicated local server plus an attached visible Steam client using `--mp-connect`, with separate write-data/config directories and the same copied mod directory. This is the fallback anticipated by architecture section 6; it changes the launch topology, not the phase's visible-action or future pause/restore acceptance criteria. Phase 04 must validate this actual topology.

Live fixes: multiplayer `remote.call` requests execute on a later tick, while a plain print may reply immediately. The transport now waits for the first actual command response before sending its delimiter; a delayed-response regression covers this ordering. Native manual placement also permits fast replacement. The executor explicitly rejects occupied collision-footprint areas before moving inventory into the cursor, including protected occupants, and verifies the resulting entity. Cursor refill is returned to inventory. The bounded footprint uses a conservative square for non-square prototypes; some otherwise legal tight placements may therefore be rejected.
