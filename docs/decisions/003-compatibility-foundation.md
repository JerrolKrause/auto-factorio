## Game foundation selection

Select a small original Lua adapter in phase 03, informed by the inspected concepts below. Do not adopt either upstream runtime or copy its mechanics. Exact revisions, notice evidence and inspected files are in the [provenance inventory](../../third_party/README.md).

FLE's `move_to/server.lua` uses a walking queue in non-fast mode, while fast mode teleports along the path and accumulates synthetic elapsed ticks. `request_path/server.lua` routes asynchronous path results by request ID, but also generates terrain chunks and adjusts the requested goal. `place_entity/server.lua` checks reach and inventory; its delayed branch uses a shared nth-tick handler, while its fast branch may search for alternate placement positions. These behaviors are coupled to FLE utilities and storage. Retain the concepts of explicit path request IDs, bounded asynchronous results, reach and inventory validation; do not port teleportation, synthetic timing, automatic terrain generation, alternate layout choices or the Python/provider/evaluation stack.

Agentic-Factorio's walker uses tick-driven character walking, correlates path replies to the active companion/task/request, and bounds retries/stuck handling. Placement resolves the item prototype's place result, approaches within build distance, checks collision and consumes an inventory item after creation. Its task lanes preserve per-character queues and terminal records, cancel active/queued work, and reject later enqueues for failed chains. The inspected build-plan code caps steps at 100 and records partial failures. These are useful concepts for deterministic execution with explicit outcomes; they do not prove AutoFactorio's save/load fencing or accounting requirements.

Agentic-Factorio's settings default to 1.6x movement speed, its companion registry caps bodies at four, and the protocol provisions starter blueprint books. Its README says MIT, but the inspected tracked tree contains no standalone license/notice text. Copying would need notice clarification as well as behavioral adaptation. The original adapter avoids that dependency and is small enough for the bounded initial action set.

Benchmark defaults exclude starter/factory blueprint libraries, speed boosts, teleportation, synthetic clocks, unrestricted console access and upstream agent-loop authority. Role identities and body counts remain independent; no four-body limit is adopted. The installed Space Age game must supply prototype facts and execute legal movement/reach, collision, inventory, crafting and mining effects. Normal-quality Nauvis is the initial target, while contracts must later accommodate surface and richer item identities. No game mechanics are implemented by this decision.
