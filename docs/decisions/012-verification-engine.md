# 012: Verification admission and measured flow

Phase 10 separates a deterministic evaluator from the operator-only Lua mutation barrier and future fixture-specific instrumentation. Global production counts, topology and gameplay claims cannot supply the evidence contract.

The barrier closes mutation admission before cancelling native crafting/mining/walking and queued batches, then records the admission tick, final receipts and character inventory. Submission and execution both enforce the same policy. An explicit matching repair abort reopens mutations. Benchmark science crafting and protected fixture rules persist. Duplicate admission reads the existing baseline; an invalidated attempt cannot silently regain admission.

The core freezes the manifest and scope. Exact engine boundaries partition settling and five one-minute windows; delayed polling without boundary evidence is invalid. Game deadlines use game ticks, wall limits require continued independent polling, and terminal attempts never earn additional output. S5's optional admission deadline is independent of its fixed finish duration and the run ceiling.

Every required stage records connected production, opposing boundary flows, consumption and both sides' container/belt/hand/in-process inventories. Fresh production, net delivery and consumption must each reach the required minimum. Versioned balance/drawdown tolerances cover measured phase effects without reducing that minimum. Fake controls demonstrate the accounting contract; their numeric tolerances are not S1 calibration.

Raw baselines, measurements, coverage, limits, window/stage results and invalidation reasons remain evaluator evidence. Human or uncertain edits mark assistance and invalidate affected attempts. The existing edit stream provides operator intervention evidence; arbitrary script/inventory changes still require fixture instrumentation to close coverage.

The phase 10 live probe exercises actual character cancellation, new/queued guards, delayed replay of cancelled work, legal walking and repair, edit invalidation and held ticks. A diagnostic player API build event supplies the human-edit control. These are guard controls, not scenario scoring. No mechanics were copied from upstream and no model inference is needed.
