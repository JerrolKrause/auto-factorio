# Legacy history and fresh game ownership

Date: 2 October 2026

Retained unfinished legacy journals do not identify the currently managed game. Import previously adopted them as exclusive owners on every startup, including when ordinary startup had just created a separate sandbox. An unknown September measurement therefore blocked a fresh October game indefinitely. Repeated import could also restore ownership of a terminal catalog request.

Ordinary startup now carries a fresh-game receipt only after successful creation and launch of a unique project profile. Before any dashboard control mutation, the dashboard verifies the receipt's nonce, profile, recent creation time, exact live server PID/start time, absence of another project game server and untouched initial control barrier. Fixed game epoch strings are not accepted as unique world identities. Supplied profiles and fixture mode do not carry this authority.

The catalog records each verified boundary once and retires ownership for imported unfinished legacy runs in one transaction. Their execution request is failed with an explicit `historical_game_replaced` reason; original unknown measurement outcomes, journal events, artifacts and provider budgets remain intact. This is evidence of isolation from the new game, not evidence that an old measurement succeeded or failed. A native journaled workshop owner may also be retired at that verified boundary when its request and registered run identify the same existing historical source, distinct from the new dashboard directory and runtime identity. Missing, inconsistent or current-runtime source identities remain held. This closes the case where a native build failure survived an ordinary fresh-game restart and blocked Stop and every successor. Same-game work and existing-profile reconnection retain exact-effect reconciliation requirements. Reimport cannot resurrect terminal catalog requests, and replaying a boundary cannot release newly discovered work.

No timeout or age threshold alone releases ownership. Reconnection to an existing game follows the existing conservative recovery path. The receipt is a trusted local startup artifact, never a browser capability or gameplay-agent tool. If verification fails, startup preserves retained ownership and reports the unconfirmed fresh-game boundary.
