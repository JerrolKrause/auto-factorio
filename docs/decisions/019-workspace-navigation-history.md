# Decision 019: local workspace identity and run inspection

The operator console uses five direct local routes under one live event connection. Direct paths, rather than the change design's proposed hash links, are served by the existing local static fallback and retain Back, Forward and refresh behavior. The Scenarios page owns current pause/resume and steering controls; the active owner banner appears across pages. Historical controls are read only except for supported current-run actions.

A project-scoped SQLite catalog under `.runtime/workspace/` indexes immutable brief/scenario groups, runs, attempts and source journals. It registers current runs and imports only the three known project run roots without mutating old journals. The original runtime journal and artifact files remain the evidence authority. Stable scoped cursors bound API reads; missing journals, legacy identities and absent invocation parts are explicit gaps. Group summaries distinguish execution from target and scenario verdicts.

Legacy timestamp reads return only the first recorded timestamp for each relevant scenario or workshop identity. A long raw activity log does not exceed the identity import bound or prevent startup; even identities created after the first 10,000 events retain their exact timestamps.

Imported workshop navigation IDs map separately to original session and attempt IDs. Reads of sessions, operations, usage, learning, invocation artifacts and events use those original identities while URLs retain catalog IDs. Repeated import repairs older catalog mappings without changing source journals. Artifact paths validate original session IDs before using them as directory names. Live terminal metadata reads share the journal's exclusive SQLite connection; only closed historical journals use a separate read-only connection.

Workshop launch admits a stable client request and exclusive game owner before preparation. The browser stores that exact pending assignment for response-loss recovery; retry does not make a new assignment. Stop persists an intent before waiting for cancellation, closes later phases, and retains ownership for an unknown effect. Startup may release a pre-journal preparation request on exact absence or a fully settled terminal session; in-flight or ambiguous provider/game effects remain held. Existing profile measurement fences are reconciled before ordinary recovery. Library and learning effects use exact durable receipts rather than speculative replay.

Stop on a held measurement asks the production host for the original operation's receipt. The durable built identity and active iteration determine the exact game attempt; matching terminal status plus terminal read, or exact not-admitted status, permits settlement and preserves the receipt in the journal. A missing fence file or an empty replacement cancellation aggregate is insufficient. Unfinished, unreadable, conflicting or unsupported effects retain ownership. Recovery never configures another measurement, starts inference, publishes a result or resets spent usage.

The host records redacted, hashed invocation parts at dispatch and observation/tool delivery boundaries. The operator inspector pages available public instructions, context, messages and output by run and attempt. It does not synthesize hidden reasoning or missing legacy transcripts. Deterministic evaluation and budget accounting remain authoritative; versioned critique and the next designer's linked change plan add actionable feedback without changing the scorer's authority. The setup draft is versioned and local to the fixed operator origin, with invalid or unavailable selections requiring explicit correction.

Async UI responses carry the page/run/group generation that requested them. Changing selection retires stale presentation without cancelling runtime execution. Pending controls prevent duplicate submissions and announce results or scoped retry errors. Library inspection and native export have a visible result panel on Library; scenario and run evidence keep their own selections.

History collections retain the pages the operator has requested during live updates. A refresh reads only the first page and the last requested page, merges stable identities in chronological order and preserves middle pages. Pagination revision checks prevent an older refresh from rewinding a newer cursor; selection or explicit retry creates a fresh scope. This keeps activity updates bounded while retaining loaded evidence and inspection selections.
