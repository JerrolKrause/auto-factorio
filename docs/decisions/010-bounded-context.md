# Decision 010: authorized bounded context

Date: 16 September 2026. Scope: phase 08, [bounded-context](../../openspec/changes/archive/2026-09-16-af-08-bounded-context/specs/bounded-context/spec.md), requirements R05/R11/R15/R16.

- Gameplay retrieval enters the coordination gateway with an opaque session credential. Each call rechecks the current session, role, observation catalog and owned/managed tasks. Async queries recheck after returning. Raw journal, artifact and export interfaces remain trusted operator APIs.
- Event visibility is the default for each projection change; an explicit per-change label can release a narrow record from a private transaction. Legacy unlabeled/operator records are not retroactively released. Ordinary gameplay commands carry their explicit task label through receipts; operator/reference execution retains the operator default even when the task later belongs to gameplay.
- The archive authorizes before projection, search, counts and pagination. References use `{ref: {entity, id}}`; existing evidence/payload fields are also filtered. Publishers must label embedded facts correctly: arbitrary prose is not an information-flow type system. Derived records carry conjunctive source references, including every authorized transitive input before flattening into snippets or payload text. Cycles, missing sources and inaccessible children fail closed. Summaries are deterministic extracts, not model-written canonical memory.
- Raw saves, checkpoint manifests and full telemetry are always excluded from gameplay retrieval. Explicit releases include only the public objective/scenario, visible-task reservation status/grants and normal scoped world symptoms. Private construction plans, seed data and detailed fault receipts are never released by changing agent roles. Operator records retain provenance for those sanitized projections.
- The three levels are `briefing` (also `observe`), `world`/`recipe`/`detail`, and authorized `history`/`payload`/`summary`. `replacement` refreshes one explicit task area and reconstructs durable memory without dispatching actions; bodyless tasks return memory with an explicit absent-world marker. It preserves separate briefing/world continuation tools and records only the composite actually delivered.
- Briefings prioritize active work and unresolved steering, with five recent outcomes/messages per selected scope. Settled older tasks remain in the archive. Terminal tasks with uncertain commands or unreleased ownership remain in the briefing until reconciliation settles their effects.
- Defaults are 16,384 serialized UTF-8 bytes and 30 aggregate array entries per response. Configurable bounds are 512–65,536 bytes and 1–50 entries. Nested lists count against the same budget; metadata objects do not add entities. Oversized records have explicit omissions and bounded JSON-text payload chunks; those chunks are text, not injected entity arrays. Archive offsets index only authorized results, with live reauthorization on every page. World pages are independent live reads; offsets are not snapshot guarantees.
- Exact sanitized delivered bytes remain separate from richer operator telemetry. Gameplay archive projections may redact references whose current visibility changed; the operator can still inspect the original bytes. Derived source closures prevent previously flattened restricted facts from surviving revocation in gameplay observations.
- Recipe facts are keyed by the sorted complete active-mod map, including `base` (the game version). Every recipe call still queries the game for current enabled state/tick. That availability never enters the facts cache. Changed facts under an unchanged fingerprint fail explicitly. This uses the existing game response and does not assert a cache of mod binaries or startup-setting files.

Implementation uses the durable journal's existing append-only events; no schema migration or dependency was needed. Archive reads currently scan the run's event history in process. This bounds delivered context, not database scan work; indexed query optimization remains a future measured need. The programmatic coordination gateway still needs the later application/provider composition; this phase does not add a gameplay launcher, dashboard or evaluator.

Validation is recorded in the [handoff](../IMPLEMENTATION_HANDOFF.md). Privacy/replacement tests use deterministic fixtures; engine smoke checks cover observations, recipes and malformed-request rejection. No provider inference is needed for this phase's gate.
