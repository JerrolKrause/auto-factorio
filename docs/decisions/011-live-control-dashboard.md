# Decision 011: local operator control and durable steering

Phase 09 builds on the phase 05–08 runtime, rather than the documentation-only baseline recorded when its proposal was first written.

- Fastify listens on `127.0.0.1` only. Every API read/write requires a per-process random capability; all requests check the exact Host and any supplied Origin, and mutations require the exact Origin. No CORS is enabled. The browser receives its capability in a URL fragment, removes that fragment and keeps it in tab session storage. SSE uses authenticated fetch, so credentials do not enter request URLs. Static assets carry a restrictive CSP. Operator access is deliberately separate from gameplay authorization.
- Snapshot projections and their cursor are read synchronously on the single SQLite writer. SSE reads bounded pages after that cursor, honors socket backpressure, and the browser ignores duplicate sequences. Reconnect reloads authoritative projections; older timeline pages remain retrievable. Closing a tab does not stop host monitoring or extend budgets.
- `Operator` persists admission closure before awaiting game or provider work. Coordinator authentication, binding, scheduling and the final dispatch guard consult that closure. An existing poll finishes behind the closed gate before a control operation changes epochs. Pause and ordinary stop preserve the world at a reconciled held barrier; resume reconciles receipts and creates fresh authority. Interrupted tasks require revised plans and grants. Inference completion and game cancellation are separate acknowledgements; an interrupt RPC alone does not prove inference ended.
- Budget exhaustion permanently closes scoring in the original run. Ordinary operator pause/stop does not erase elapsed wall time or spent turns. A disconnected or uncertain world remains closed to new work. Checkpoint status never claims a disk save: these controls do not implicitly create checkpoints.
- Advice is persisted with an idempotency fingerprint, exact ordinary text, recipient and both clocks before delivery. When the game is disconnected, its game clock is explicitly unknown. Existing credential redaction still applies. Receipt means availability in the recipient's bounded, authorized briefing; interpretation is a separate authenticated gameplay operation with task links. Neither state changes assignments or cancels an active batch.
- Game edit hooks observe player building, mining, rotation, settings paste and tile changes. Synchronous executor callbacks and matching controlled mining targets are excluded; unmatched overlap is recorded with unknown causality. The operator persists assistance and invalidates an active verification attempt. Script changes and arbitrary inventory edits are not exhaustively covered. The game buffer is bounded at 2,000 entries and overflow invalidates evidence rather than silently dropping its completeness claim. Phase 10 consumes these integrity records; this phase does not implement scoring.

The launcher is an operator host, with registered roles, the existing coordination/gateway interfaces and lifecycle callbacks. `--fixture` is an explicitly synthetic UI demonstration. Live game checks use synthetic role callbacks, not fresh model inference. An autonomous provider/scenario driver remains part of the later scenario/trial composition; no API billing or automatic model calls are introduced.
