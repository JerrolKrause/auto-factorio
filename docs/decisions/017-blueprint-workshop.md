# Decision 017: blueprint workshop and bounded maintenance

## Decision

Implement a local blueprint workshop around versioned assignments, installed-data capability profiles, immutable library revisions, two construction paths and evaluator-owned exact-window scoring. Deterministic code owns scheduling, calculations, placement compilation, measurement and activation. Managed model contexts are limited to design, critique and evidence-based maintenance roles with exact OpenAI model/effort selections and no paid/API fallback.

Direct placement and unlimited allowed supplies are scoped to isolated workshop surfaces. Ordinary runs reuse library artifacts through legal finite-inventory character batches. Native blueprint strings contain only Factorio-supported fields; interfaces, compatibility and evidence stay in an optional sanitized sidecar. Multiple useful variants remain distinct immutable revisions.

The dashboard submits operator-owned options with a brief, preset or existing revision; an authorized orchestrator may submit the full contract. Real dashboard and scenario entrypoints construct the trusted production host from an attached project game and an absolute managed Codex executable after catalog/authentication preflight. Every launch mode is revalidated against running prototypes and persisted with the current fingerprint. Improve loads the exact compatible parent document before inference. A runtime-owned background driver advances the journal independently of browser lifetime. Brief, after-score, library-admission and learning-activation checkpoints are durable decisions with restart-safe deadlines. Gated admission runs only after continue; learning first records a no-change or proposal outcome and pauses only when a fully attested concrete bundle is ready to activate. Library status, compatibility and useful distinction are derived from the exact eligible score, evaluation, comparable immutable revisions and export/build checks; no authenticated HTTP caller can author verification labels. Direct materialization and finite character provisioning roll back every mutation from a failed operation before that operation may be retried.

One durable session budget owns designer, scorer and learnings invocations. It preserves aggregate turns, tools, elapsed provider time and reported tokens across role calls and restart, partitions time and finite tokens by the configured learning turn/tool share, and records stable invocation attribution. Unknown finite-token use closes later inference for that owner; any admitted maintenance failure records a deferred outcome without invalidating completed blueprint work. Unsupported or restored model selections are rechecked without fallback. Dispatched external effects are acknowledged durably; after controller replacement, adapters reconcile known receipts and unresolved effects remain held instead of being replayed. Stop and shutdown request provider/game cancellation before waiting for active tasks. Both adapters must return confirmed terminal or cancellation receipts; rejection or the absence of a game-side receipt leaves the effect and session held.

Learning may autonomously change typed, registered designer/scorer instructions, scoped lessons and design-helper functions. This authority excludes provider choices, budgets, permissions, objectives, rubrics, measurement code, private controls and activation rules. After-session, bounded-batch and off cadence persist typed outcomes; no-change or deferred maintenance completes without an activation pause. Every new bundle overlays its change on the complete effective incumbent and retains the incumbent's control obligations. Regression, interaction, representative behavior and fresh read-only review therefore attest the exact cumulative bytes, complete cumulative control set and incumbent generation. Behavior evidence is required for every nonempty bundle, including lesson-only changes. Every applicable result must pass conclusively; a conflicting failed or inconclusive result keeps the bundle inactive. Atomic compare-and-swap, session pins, exact active instruction/lesson/helper consumption, quarantine and rollback preserve history.

Activated helper functions run in a separate permission-restricted Node process and a capability-free VM context with bounded structured input/output, scratch, wall time, memory and invocation count. The privileged runtime never imports helper code and admits only revision-matched registered suggestion/constraint plans into the designer observation. Pinned lessons use the bounded declared retrieval field, and the session retains consumption or rejection evidence. A missing or violated boundary rejects the helper without fallback; blueprint completion does not depend on activation. Library admission binds persisted scores to the canonical full rubric hash, so a reused version label cannot reinterpret older evidence.

## Supported boundary

The initial matrix covers deterministic normal-quality solid/fluid recipes with assemblers, furnaces, chemical/oil machines, electromagnetic plants and foundries where the profile permits them, plus supported transport, modules, beacons, basic entity settings and wires. It rejects stochastic/spoilage behavior, quality generation, trains, platforms, advanced circuit programs and dedicated mining/power designs. Current live evidence establishes direct placement, EM/foundry surface rules, configured multi-fluid/byproduct content, character reconstruction, positive normal/accelerated exact windows, exact threshold and burst/starvation/settling-stock controls, managed save/load recovery and no-mod blueprint/book import; it does not claim universal late-game support.
